# Tech Docs Blog Writing

**总原则：文档和博客的存在意义是有价值。** 这篇东西让读者多得到什么，答不出来就不写。下面所有规则都是这条的展开；与它冲突时，以它为准。

读者愿信、愿照着做。一处假证据毁整页。无过程性废话。

博客：一事一篇。只回答一个问题，答完即停。小 bug 说透复现与修法即可；删掉不影响该事的段落一律删。不为凑体裁堆背景、启示或横评。

## 模式

| 模式 | 做 |
|------|----|
| 起草 | 定件 → 选题 → 体裁 → 主张账本 → 写 → 去 AI 腔 → 出门 |
| 修订 | 「读者多知道了什么」说不清则停。P0/P1/P2 列问题；未经允许不全文重写 |

## 定件

体裁、读者、一句判断、证据边界、发布面。能推断则不问。

先过价值闸门：读者读完能多做什么、或能少错什么？答得出才能往下走。

无意外 / 测量 / 强观点之一：不写。

中文须有实践增量：命令、版本号、错误码、数字、失败路径、配置坑。

## 选题

博客至少命中：反直觉 / 反叙事 / 意外能力 / 精确定名 / 共鸣。

## 体裁

一页一事。标题一个主张。开篇先结论。

### 文档

| 类型 | 骨架 |
|------|------|
| Tutorial | 结果预览 → 前置 → 可验证分步 → 完整代码 → 下一步 |
| How-to | 目标 → 前提 → 步骤 → 验证 → 失败 |
| Reference | 按 API/表面穷尽；条目可独立引用 |
| Conceptual | 是什么 → 为何 → 模型 → 例子 → 何时不用 |
| Troubleshooting | 症状 → 排查树 → 修复 → 预防 |

### 博客

有对应素材才选模式；无素材不硬凑。

| 素材 | 模式 | 可信度靠 |
|------|------|----------|
| 时间线+意外 | 踩坑 | 死胡同 |
| 易错概念 | Explainer | 常见误解 |
| 系统+决策 | How We Built It | 取舍 |
| 前后数字 | Rewrite | 变糟之处 |
| 多事故同题 | Lessons | 每条一个故事 |
| 对比测量 | 横评 | 方法学先于结果 |

小 bug：现象 → 复现 → 根因 → 修法。

其余按需：问题 → 怎么工作 → 取舍 → 怎么用/复现 → 失败与极限。

## 主张账本

断言只属：`Measured` | `Shown` | `Sourced` | `Opinion`。

无类：删 / 降为 Opinion / 补证据。性能主张最严。

横评披露：硬件、版本、负载、配置、复现方式。

## 硬规则

1. 文档类不考虑兼容性
2. 有判断；落到版本号与错误码
3. 禁空壳标题与 Q&A 式 H3
4. 数字压过形容词；条件式选型，不排名
5. 代码可运行，标语言；注释写 why
6. 有决策写没选什么；优劣写事实与代价
7. 读者「你」；步骤祈使；「我们」仅真实团队行为

## 禁

兴奋宣布、业界领先、赋能、无缝、easy/simple、显著/大幅、最完整/最成熟/最优解/无可替代/极致、本文将探讨、众所周知、至关重要、希望对你有帮助。

## 去 AI 腔

整句重写，禁止换词。每句须有新信息。默认不用「不是 A，而是 B」「不仅…而且…」（纠正真实误解除外）。拆翻译腔（对于…来说 / 基于… / 使得…得以…）。判断先机制后结论。有文风样本则跟样本；禁止伪造人设。

技术文要可导航，禁止版式对称：

| 留 | 打散 |
|----|------|
| How-to 编号、参考穷尽、能力表、前置清单 | 连续 ≥3 节同构、句句等长、硬凑三点、段末拔高、先…再…最后…串篇 |
| H2 可读、代码语言标签 | 叙述节同厚；两句拆成 bullet 墙 |

连续两节以上「定义→列举→小结」必须打散。两项优于三项。Reference 可整齐；博客与概念叙述必须错落。

| 腔 | 改成 |
|----|------|
| 不是配置问题，而是发布过期 | 发布物过期了，配置没问题 |
| 至此我们完成了配置。接下来… | 直接写下一步 |
| 没有错误。没有告警。一片绿灯 | 当时没有错误和告警 |
| 支持某某能力，提供灵活配置 | 打开 `foo.enabled`；超时默认 30s |
| 在快速变化的技术浪潮中… | 删；第一句写结论或故障 |
| 希望本文对你有帮助 | 复现命令或链接 |
| 最成熟的开源 IAM | 可验证事实 + 适用条件 |
| 三节同构 / 等长排比 | 按内容变节长；合并同构句 |

不删：术语（可挂括号）、mermaid/流程图图标、代码示例输出、有判断的小结。

能力矩阵不用 ✅❌⭐⚠️ 当状态；整格仅符号才改「支持/不支持」；符号后有字只删符号。

## 出门

- [ ] 价值成立：说得出读者多得到什么
- [ ] 主张有证据；有判断；有版本/错误码
- [ ] 开篇结论；标题一主张；H2 可读
- [ ] 无营销/夸大/AI 腔；叙述不对称过齐；术语未误删
- [ ] 代码可跑或已标明未跑
- [ ] 结尾有下一步
- [ ] 博客一事说透、无堆砌；否则进文档/changelog

列出仍需人确认项。
